MOSS：高效、精确的 FP8 LLM 训练，采用微尺度和自动尺度变换

2026-11-12T13:50:00.000Z2026-11-12T13:54:26.046Z青岛

MOSS：高效、精确的 FP8 LLM 训练，采用微尺度和自动尺度变换

1. MXFP8 的量化逻辑

MXFP8 的核心计算逻辑是：每 32 个连续数值作为一组，找到这组里绝对值最大的数，据此算出一个只表示“2 的幂次”的共享缩放因子，然后用这个因子去除组内每个数，把结果存成 FP8。

2. 信噪比是什么

信噪比（Signal-to-Noise Ratio，SNR）是衡量有用信号强度相对于噪声强度的指标。在论文里，它用来评价量化后的张量与原张量有多接近：SNR 越高，量化噪声越小，量化保真度越好。

基本定义

SNR 是信号功率与噪声功率之比：

通常用分贝（dB）表示：

  • SNR = 0 dB：信号功率和噪声功率相等。
  • SNR 越高：噪声相对信号越小，质量越好。
  • SNR 为负：噪声比信号还强。

论文为什么用 SNR

FP8 只有 8 位，量化的核心问题是“量化后损失了多少信息”。SNR 把这种损失量化成一个可比较的数，于是可以公平比较不同量化方案：

  • per-tensor 量化；
  • per-group 量化；
  • MOSS 的两级微缩放。

论文 Table 7 就是用 SNR（dB）比较这三种方案。结果显示 MOSS 的 SNR 比 per-group 高约 3.0–3.4 dB，比 per-tensor 高约 9.2–9.4 dB，说明 MOSS 量化误差更小。

一个直观类比

把原始张量想成一首歌，量化误差想成背景杂音。SNR 就是“歌声音量 / 杂音音量”。杂音越小，SNR 越高，听感越接近原唱。论文里的“原唱”是 FP32/BF16 张量，“翻唱”是 FP8 量化再反量化的结果，SNR 衡量翻唱有多接近原唱。

注意 dB 是对数尺度

SNR 提高 3 dB 大约意味着噪声功率减半，提高 10 dB 意味着噪声功率降到约十分之一。所以论文中“高 3 dB”不是微小差距，而是量化噪声显著降低。

4. 为什么要进行两级微缩放

先看现有 per-group 量化的问题

论文 1 节和 3.1 节反复强调，当前 FP8 训练框架（如 COAT）对激活做 per-group 量化，每个 128 值组一个 FP32 缩放因子。这样做数值上很准，但有个致命效率问题：

缩放因子是沿着 GEMM 的内维 K 分布的。Tensor Core 做完一段乘加后，要在 CUDA Core 上把 partial sum 乘以对应的组缩放因子再累加。而 CUDA Core 的 FP32 峰值吞吐只有 FP8 Tensor Core 的 1.6%，反量化一次 partial sum 的代价约等于 60 次 Tensor Core MAC。结果 GEMM 主循环被慢速反量化拖垮。

Figure 1 显示：per-group 的 COAT 吞吐远低于 per-tensor 的 Transformer Engine。所以per-group 太贵。

那退回 per-tensor 行不行？

per-tensor 只有一个 FP32 因子，GEMM 主循环可以全在 Tensor Core 上跑，反量化放到 epilogue，效率高。但精度不够：LLM 激活有离群值，整个张量共用一个因子，小值被压得很惨，SNR 低（Table 7 显示 per-tensor 比 per-group 低约 6 dB）。

于是矛盾是：

  • per-tensor：快，但精度差；
  • per-group：精度好，但主循环里反量化太贵。

两级微缩放的思路：把“贵的高精度缩放”放粗粒度，把“便宜的细粒度缩放”放细粒度

MOSS 的出发点是：能不能既保留细粒度对局部动态范围的适应，又不让 GEMM 主循环里做昂贵的 FP32 反量化？

答案是把缩放拆成两层：

  • Level-1 全局因子 ：FP32，粗粒度（整个 范围共享），精度高但数量少。它只在 epilogue 里用一次，不在主循环里反复乘，所以贵一点没关系。
  • Level-2 局部因子 ：E8M0（2 的幂），细粒度（每 32 值一个），但格式极便宜，E8M0 乘法可以融进 Tensor Core 的 MMA 里（相当于指数偏移），不需要 CUDA Core 做 FP32 乘法。

这样，细粒度缩放由便宜的 E8M0 承担，高精度由粗粒度的 FP32 承担，GEMM 主循环里只有 Tensor Core 操作，反量化全部推迟到 epilogue（Figure 3b）。这就是“两级”的出发点。

5. 自动缩放

自动缩放（automatic scaling）是 MOSS 为权重设计的一种缩放因子确定方法。它的核心原理是：利用 Adam/AdamW 优化器的“更新有界性”，也就是权重每一步的变化量被学习率 限制住，从而提前预测权重最大绝对值的增长上界，直接算出缩放因子，而不必每步去 HBM 里读权重、做 max-reduction。

下面按“问题—原理—公式—做法—效果”拆开讲。

要解决的问题：just-in-time scaling 太贵

FP8 量化需要缩放因子 ，保证权重落在 FP8 动态范围内。传统做法是 just-in-time（JIT）缩放：每一步都读整个 FP32 权重张量，算最大值，再写回 FP8。论文 Table 1 显示，对大张量这一步要 0.54 ms；而且涉及多次 HBM 读写，抵消了 FP8 的性能收益。

和 JIT、delayed scaling 的区别

  • JIT scaling：每步读当前权重算 max，最准但最贵（多次 HBM 读写）。
  • Delayed scaling：用历史窗口的最大值估计当前缩放，假设统计一致，遇到离群值可能失稳。
  • 自动缩放（MOSS）：利用 Adam 更新有界性预测缩放因子上界，区间内零 max-reduction，区间末重校准。它既不是“看历史”，也不是“看当前”，而是“按优化器性质推算上界”。

一句话总结

自动缩放的原理是：Adam/AdamW 每步对权重的更新幅度被学习率 界住（），所以权重最大绝对值随时间至多线性增长 ；据此直接预测缩放因子 ，只在初始化做一次 max-reduction，之后区间内零开销、区间末重校准，从而在保持精度的同时消除 JIT 缩放的内存访问和 max-reduction 成本。
